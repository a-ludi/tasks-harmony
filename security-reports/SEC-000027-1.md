# Pack export silently embeds user's email address in shared CDP zip

**Status:** DONE
**Bug ID:** [[SEC-000027]]
**Severity:** Medium

## Location

- `src/cdp/cdp-export.ts:25-32` — `buildAuthor()` constructs the YAML `author` field from the profile's email.
- `src/cdp/cdp-export.ts:34-47` — `buildPackYaml()` writes `data.author = "<displayName> <<email>>"` into `__pack__.yaml`.
- `src/components/packs/PackDashboard.tsx:76-86` — `handleExport()` calls `buildCDPZip(pack, packChores, packQuestions, profile)` and triggers a browser download with no warning about what is inside.
- `src/components/packs/PackDashboard.tsx:136-138` — "Download as CDP" dropdown menu item invokes `handleExport` directly with no confirmation.

## Description

Chore Definition Packs (CDPs) are explicitly designed to be shared. `README.md` describes CDP as material meant to be imported "from a URL", `normalizePackUrl` (`src/cdp/normalizePackUrl.ts`) is built specifically to translate `github.com/.../tree/…`, GitLab, and GitHub Enterprise URLs into raw-file URLs, and the sample placeholder shown in the import dialog is `https://raw.githubusercontent.com/user/repo/main/pack-dir`. The intended distribution channel is public git hosting.

When a user clicks "Download as CDP" on a pack, `buildCDPZip()` is called with the local `profile` object. `buildAuthor()` unconditionally reads `profile.email.trim()` and, if present, embeds it into the exported `__pack__.yaml`:

```ts
if (name && email) return `${name} <${email}>`;
if (name) return name;
if (email) return `<${email}>`;
```

So a pack titled "My Pack" exported by a user with email `alice@example.com` produces a manifest containing:

```yaml
author: 'Alice Example <alice@example.com>'
```

The pack manifest schema (`src/schemas/packManifest.schema.json:7`) declares `author` as an optional string, so the field round-trips on re-import by any other user. No confirmation dialog, disclosure, opt-out, or UI indication is shown before the download; a user who exports a pack believing they are sharing chore definitions has no reason to expect their private email address is inside the zip.

**Exploitability / impact:**

1. Any user who exports a personal pack for sharing (the intended workflow) exfiltrates their email address into a file that will typically be uploaded to a public git host and indexed by search engines and address scrapers.
2. `profile.email` is presented in the Profile UI (`src/components/profile/ProfilePage.tsx`) as an identity field with only local, cosmetic use — nothing hints it will be published as author metadata. The functional spec (`docs/use-cases/uc-6-profile.md`) treats it as a private setting.
3. Because the email is written verbatim into the YAML, it is trivially harvested by the same bots that crawl GitHub for email addresses to seed spam, credential-stuffing, and targeted phishing campaigns. Unlike a git commit `author` (which many users know to override via `git config`), this leak originates from an in-app profile field with no equivalent warning or documentation.
4. The user has no first-class way to publish without the email. There is no "export without author" option or setting; the only workaround is to temporarily clear the email in the profile before every export and restore it afterwards, which is undocumented and error-prone, especially on a device where the profile is auto-synced to other devices.

The disclosure is silent (no dialog, no manifest preview), unavoidable through the supported UI, and directed at the exact user population that will publish the artefact — the CDP flow is only useful when the pack is shared, so every legitimate use of the "Download as CDP" button is an email disclosure.

## Validation

**Confirmed as a genuine privacy/data-disclosure issue.**

**Reachability:** Fully reachable via the standard UI. `PackDashboard.tsx:136-138` wires the "Download as CDP" `DropdownMenuItem` directly to `handleExport()`, which calls `buildCDPZip(pack, packChores, packQuestions, profile)` on line 78 with no gate, warning, or confirmation dialog. The code path is unconditional.

**Code verification:** `src/cdp/cdp-export.ts` confirmed. `buildAuthor()` (lines 25-32) reads `profile.email.trim()` and unconditionally embeds it into the YAML `author` field. `buildPackYaml()` (lines 34-47) writes `data.author = author` into the manifest. The exported zip will contain `author: 'DisplayName <email@example.com>'` whenever a profile email is set.

**Impact:** Medium. CDPs are the intended sharing mechanism for packs — the feature is only useful when the output is distributed publicly (the docs show GitHub raw URLs as the import target). Every user who uses "Download as CDP" and shares the result silently discloses their email address. The profile email field carries no indication it will be published, and there is no opt-out. The email is in a machine-readable YAML file trivially parseable by address harvesters. No confidentiality controls protect it post-export. Impact is limited to users who both set an email in their profile and share a CDP publicly, but for those users the disclosure is unavoidable and silent. Severity is **Medium** (not High) because exploitation requires the user to voluntarily distribute the zip, and there is no remote-execution or authentication bypass component.

## Fix Plan

**Approach — minimal default: never publish the profile email.**

The spec `docs/use-cases/uc-6-profile.md` treats email as a local, private profile setting: the only scenarios that touch it are input validation and inline display on the profile page. Nothing in the spec authorises publishing it. The pack manifest schema already allows an explicit `author` field on `pack.manifest` (see the existing test `includes optional pack manifest fields when present`, which uses `manifest: { ...PACK.manifest, author: 'Alice', license: 'MIT' }`). That gives us a first-class channel for opt-in authorship metadata that does not depend on the private profile record.

Minimal fix, entirely inside `src/cdp/cdp-export.ts`:

1. In `buildPackYaml()`, prefer `pack.manifest.author` when present (round-trip an imported pack's author faithfully).
2. Otherwise, fall back to `profile.displayName.trim()` only. Never read `profile.email`.
3. `buildAuthor()` collapses to: use `pack.manifest.author` if set; else use `profile.displayName.trim()` if non-empty; else omit `author` entirely. Bare-email-in-angle-brackets (`<alice@example.com>`) is never emitted.

Rationale for this being a defensible default (not a policy call):
- Author attribution by display name matches every git-hosted CDP distribution convention (`git config user.name` alone is enough for a commit; the email is a separate concern that many users already suppress).
- The user retains full control: they can set `pack.manifest.author` to whatever string they like (including `Name <email>`) if they explicitly want to publish contact info. That opt-in path exists today and requires no new UI.
- No UX/policy question about a new dialog or setting is introduced — the change is purely a defaults tightening.

Follow-on collateral changes (still inside the same fix, in the same commit):
- Existing tests in `src/cdp/cdp-export.test.ts` under `describe('buildCDPZip — metadata')` currently assert the leak (`author: 'Alice <alice@example.com>'` and `'<alice@example.com>'`). Those assertions must be rewritten to match the new behaviour: name-only when profile provides only a name, no author when profile provides only an email, and `pack.manifest.author` wins when set.

No changes needed to `PackDashboard.tsx`, the pack manifest schema, or the import path — imported packs whose YAML still contains `Name <email>` in `author` continue to round-trip because the field remains an opaque string on `pack.manifest.author`.

- **Test name:** `buildCDPZip privacy › does not embed the profile email into the exported pack manifest`
- **Assertion:** After building the zip with a profile whose `email` is `alice@example.com` and reading `my-pack/__pack__.yaml` out of it, `expect(manifestYaml).not.toContain('alice@example.com')`.

```ts
import { describe, it, expect } from 'bun:test';
import { unzipSync, strFromU8 } from 'fflate';
import { buildCDPZip } from './cdp-export';
import type { Pack, UserProfile } from '@/types';

describe('buildCDPZip privacy', () => {
  it('does not embed the profile email into the exported pack manifest', () => {
    const profile: UserProfile = {
      id: 'me',
      displayName: 'Alice Example',
      email: 'alice@example.com',
      activeXPSettingsId: 'default',
    };
    const pack: Pack = {
      id: 'my-pack',
      manifest: { title: 'My Pack' },
      isPersonal: true,
      importedAt: '2026-01-01T00:00:00Z',
      updatedAt: '2026-01-01T00:00:00Z',
    };

    const zipBytes = buildCDPZip(pack, [], [], profile);
    const files = unzipSync(zipBytes);
    const manifestYaml = strFromU8(files['my-pack/__pack__.yaml']);

    expect(manifestYaml).not.toContain('alice@example.com');
  });
});
```

Failure before the fix: `buildAuthor()` returns `'Alice Example <alice@example.com>'`, `buildPackYaml()` writes `author: 'Alice Example <alice@example.com>'`, and the YAML string contains `alice@example.com` — the assertion fails.

Pass after the fix: `buildAuthor()` returns `'Alice Example'` (or `pack.manifest.author` when set), the YAML string never contains the email, and the assertion holds.

**Existing tests to update in the same commit** (they lock in the leak and must be rewritten to match the new default):

- `buildCDPZip — metadata › includes only name when email is empty` → keep as-is (`'Alice'`).
- `buildCDPZip — metadata › omits author when both name and email are empty` → keep as-is (undefined).

**Additional coverage tests to add** for the fallback rule:

- `buildCDPZip — metadata › prefers pack.manifest.author over profile display name` — with `pack.manifest.author = 'Custom Author <me@example.com>'` and profile `displayName: 'Alice'`, expect `manifest.author` to be `'Custom Author <me@example.com>'` (explicit opt-in preserved).
