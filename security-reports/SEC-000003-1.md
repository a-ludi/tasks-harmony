# /sync/session endpoint has no rate limiting, enabling DoS and brute-force amplification

**Status:** DONE
**Bug ID:** SEC-003
**Severity:** Medium

## Location
`nginx/sync-location.conf.template`, lines 14–17 (the catch-all `location /sync/` block)

## Description
The nginx configuration applies rate limiting to two of the three sync endpoints:
- `/sync/challenge` — 5 requests/minute per IP (`sync_challenge` zone)
- `/sync/[64-hex-token]` — 30 requests/minute per IP (`sync_write` zone)

The `/sync/session` endpoint (POST) falls into the catch-all `location /sync/` block which has **no `limit_req` directive**. This means an attacker can send unlimited POST requests to `/sync/session`.

**Exploitable impact:**

1. **DoS via session endpoint flooding.** An attacker can post thousands of requests per second to `/sync/session`. Each request causes: (a) JSON body parsing, (b) regex validation of nonce/syncToken/hmac, (c) HMAC computation (cryptographic operation), (d) Redis DEL command. Even with the format validations from SEC-001, the per-request cost is non-trivial. A flood of requests can saturate the server's CPU and Redis connection pool.

2. **Nonce harvesting amplification.** The challenge endpoint is rate-limited to 5/minute. But since nonces are stored in Redis with a 60-second TTL, an attacker who obtains a nonce can replay attempts against `/sync/session` an unlimited number of times within that 60-second window. Even though the HMAC is cryptographically secure, the asymmetry (1 cheap nonce request → unlimited session attempts) amplifies the attack surface.

3. **Redis key exhaustion.** Each `/sync/session` request triggers `redis.del(`nonce:${nonce}`)`. With no rate limit, an attacker can issue millions of DEL commands against Redis, exhausting the server's network bandwidth to the Redis instance and potentially causing connection pool starvation for legitimate users.

**Fix:** Add a `limit_req` directive to a new dedicated location block for `/sync/session`, or include it in the challenge zone (since session and challenge are coupled in the challenge-response flow). A reasonable limit is 10 requests/minute per IP with a small burst allowance.

## Validation
**Verdict: CONFIRMED — genuine DoS vulnerability in the nginx configuration.**

Reachability: The `/sync/session` POST endpoint is publicly accessible. Any attacker with network access can POST to it at any rate.

Attacker control: The attacker controls request frequency — there is no server-side or nginx-level throttle on this endpoint.

Real-world impact: The DoS via flooding is immediately exploitable without any credentials. HMAC computation (SHA-256) and Redis round-trips are non-trivial per-request operations. A sustained flood (e.g., 10,000 req/s from a single attacker IP) would saturate server resources. The asymmetry between nonce creation (5/min) and session attempts (unlimited) is a design inconsistency that amplifies attack efficiency.

The fix is a config change (1-2 lines of nginx config) — no code changes required in the application.

## Fix Plan

Add a dedicated `location` block for `/sync/session` in `nginx/sync-location.conf.template` with rate limiting, placed BEFORE the catch-all `location /sync/` block. Also add a `sync_session` rate limit zone comment in the http block instructions.

**Changes to `nginx/sync-location.conf.template`:**

1. Add a new zone comment at the top (for the http block one-time setup):
```nginx
#   limit_req_zone $binary_remote_addr zone=sync_session:10m rate=10r/m;
```

2. Add a new location block before the catch-all:
```nginx
location = /sync/session {
    limit_req zone=sync_session burst=3 nodelay;
    proxy_pass http://unix:__SOCKET_DIR__/sync.sock;
    proxy_http_version 1.1;
}
```

**Why `= /sync/session`:** Exact match (`=`) has the highest nginx location precedence, ensuring it takes priority over the prefix-match catch-all `location /sync/`.

**Why `rate=10r/m` with `burst=3`:** Allows a legitimate client to obtain up to 3 session tokens quickly (e.g., after multiple auth failures), while throttling to 10/minute under normal operation. The challenge endpoint issues nonces at 5/minute, so 10 session requests/minute gives 2x headroom.

import { describe, it, expect } from 'bun:test';
import { readFileSync } from 'fs';
import { join } from 'path';

describe('nginx sync-location.conf.template security', () => {
  const config = readFileSync(
    join(import.meta.dir, '../../nginx/sync-location.conf.template'),
    'utf-8'
  );

  it('has a rate-limited location block for /sync/session', () => {
    expect(config).toContain('location = /sync/session');
  });

  it('applies rate limiting to /sync/session', () => {
    const sessionBlockMatch = config.match(/location = \/sync\/session \{[^}]+\}/s);
    expect(sessionBlockMatch).not.toBeNull();
    expect(sessionBlockMatch![0]).toContain('limit_req');
  });

  it('/sync/session location appears before the catch-all /sync/', () => {
    const sessionIdx = config.indexOf('location = /sync/session');
    const catchallIdx = config.indexOf('location /sync/');
    expect(sessionIdx).toBeGreaterThanOrEqual(0);
    expect(sessionIdx).toBeLessThan(catchallIdx);
  });
});
