# AppState schema leaves `pack.manifest` unvalidated, allowing arbitrary structure in imported backups

**Status:** DONE
**Bug ID:** SEC-000030
**Severity:** Medium

## Location
- `src/schemas/appState.schema.json` lines 8–24 (the `packs.items.manifest` field)
- `src/sync/import.ts` `importAppState` — writes the unvalidated manifest object straight into the `packs` object store
- `src/components/profile/ProfilePage.tsx` `handleImport` — trusts `validateAppState` before calling `importAppState`
- `src/sync/server.ts` `pull` — same trust boundary for encrypted-sync ingest

## Description
`appState.schema.json` tightened array items with `additionalProperties: false` under SEC-000023, but the `manifest` field of every pack is still declared as:

```json
"manifest": { "type": "object" }
```

That is: no `properties`, no `additionalProperties: false`, no `required` fields. AJV therefore accepts any object shape at all under `manifest`, including:

- keys not defined by `packManifest.schema.json` (which enforces `additionalProperties: false` for CDP-imported packs, but is not consulted during `validateAppState`);
- wrong types for known keys (`title: 123`, `description: { evil: "…" }`, `xpTarget: "9e99"`);
- reserved keys like `__proto__`, `constructor`, `prototype` that only survive when carried by a hand-crafted JSON blob (e.g. `Object.defineProperty(obj, '__proto__', { value: … })` before `JSON.stringify`) — bypassing the JSON.parse own-property filter is nontrivial, but nothing in the current schema stops the raw payload from persisting once inside IndexedDB.

Reachable via two attacker-controlled ingress paths:

1. **Plain-ZIP backup import** (`ProfilePage.handleImport` → `unwrapStateFromZip` → `validateAppState` → `importAppState`). An attacker who convinces the victim to import a `.zip` gets full control over `pack.manifest`. Note that `isAppStatePristine` gates the destructive confirm only on `packs.length === 0 && completions.length === 0`, so a fresh install imports with no confirmation at all.
2. **Encrypted-sync pull** (`sync/server.ts` `pull` → `decryptState` → `validateAppState` → `importAppState`). Anyone who possesses the sync key (e.g. exported `.json` key file that leaked) can PUT a crafted blob and, at the victim's next pull, the malicious manifest lands in the local `packs` store.

Concrete post-conditions when a crafted pack lands in IndexedDB:

- `pack.manifest.description` is passed to `<MarkdownDisplay content={pack.manifest.description} />` (`src/components/packs/PackDashboard.tsx:197-198`). If `description` is not a string, milkdown's default-value ctx receives a non-string, which sanitizeMarkdownLinks then invokes `.indexOf` on — the entire pack dashboard route crashes, and because the pack is now persisted the crash is *sticky*: the victim cannot navigate to that pack until they manually purge IndexedDB.
- `pack.manifest.xpTarget` feeds `Math.min(1, packXP / pack.manifest.xpTarget)` and `packXP >= pack.manifest.xpTarget` (`PackDashboard.tsx:50-68`). A hostile string/object/NaN produces NaN comparisons and renders the "target date" branch with junk values, and a huge number can be used to silently hide legitimate progress.
- `pack.manifest.allowShiftOnImport`, `streak`, `defaultXPSize`, and `decay` are all read without runtime type-checks throughout `PackOptionsModal.tsx` and `store/index.ts`; wrong-typed values break these controls and are round-tripped back to sync/backup.
- Because `packs.items.additionalProperties: false` does NOT recurse into `manifest`, arbitrary keys survive the export→import→sync cycle, so a single successful import permanently contaminates the account.

The `packManifest.schema.json` file already defines the correct closed shape (with `additionalProperties: false`), but `validate.ts` never uses it when validating an `AppState` — it only validates it standalone against a raw CDP manifest fetch. That is the discrepancy: CDP fetches from an arbitrary URL are strictly validated; but backups and sync payloads — which have the *same* trust properties as a random CDP URL — are not.

This gap has the same root cause as SEC-000023 (which strengthened array items) and is a direct continuation of that fix left incomplete.

## Validation

**Status: CONFIRMED — Medium**

This is a genuine, exploitable security issue and a distinct follow-up to SEC-000023.

**Not a duplicate.** The four completed reports cover unrelated topics (cache headers, HMAC auth, key exfiltration, DoS quota). SEC-000023-1 is a fixed report (excluded from duplicate checking), and it explicitly deferred manifest deep-validation with the comment "deep validation happens via `validatePackManifest` at CDP import; here we just gate the shape." SEC-000030 is precisely that deferred gap.

**Reachability confirmed.** Two attacker-controlled ingress paths both reach `importAppState` after only `validateAppState`:

1. `ProfilePage.handleImport` → `unwrapStateFromZip` → `validateAppState` → `importAppState` (plain ZIP, no confirmation on fresh install)
2. `sync/server.ts pull` → `decryptState` → `validateAppState` → `importAppState` (encrypted-sync channel with a stolen/shared key)

**Attacker control confirmed.** `appState.schema.json` line 15 declares `manifest` as `{ "type": "object" }` with no `properties`, no `required`, and no `additionalProperties: false`. AJV therefore accepts any object shape. `packManifest.schema.json` (which has `additionalProperties: false` and typed fields) is compiled in `validate.ts` but is never applied during `validateAppState` — only during standalone CDP manifest fetches.

**Real-world impact confirmed:**

- `pack.manifest.description` (when not a string) is passed as-is to `MarkdownDisplay` → `sanitizeMarkdownLinks` which calls `.indexOf` on it, crashing the entire pack dashboard route. Because the pack is persisted in IndexedDB the crash is sticky — the victim cannot access that pack without manually purging IndexedDB.
- `pack.manifest.xpTarget` feeds `Math.min(1, packXP / pack.manifest.xpTarget)` and `packXP >= pack.manifest.xpTarget`. A hostile string/object/NaN produces NaN comparisons and corrupted rendering.
- Other manifest fields (`allowShiftOnImport`, `streak`, `defaultXPSize`, `decay`) are read without runtime type-checks in `PackOptionsModal.tsx` and `store/index.ts`; wrong types break these controls.
- Arbitrary extra keys survive the full export→import→sync cycle, permanently contaminating the account.

**Severity: Medium.** Direct exploitation requires convincing the victim to import a crafted ZIP (social engineering) or requires possession of the victim's sync key (already a significant prerequisite). The impact — sticky UI crash and data corruption — is significant but does not constitute remote code execution or credential theft. The gap is real and should be closed by referencing `packManifest.schema.json` (or inlining its constraints) for the `manifest` field in `appState.schema.json`.

## Fix Plan

**Root cause.** `src/schemas/appState.schema.json` line 15 declares the `manifest` slot inside `packs.items` as bare `{ "type": "object" }` with no `properties`, no `required`, and no `additionalProperties: false`. SEC-000023 closed the same gap on the surrounding pack object but explicitly deferred deep manifest validation with the note "deep validation happens via `validatePackManifest` at CDP import; here we just gate the shape." However, `validatePackManifest` is never invoked on the AppState import/pull path (`ProfilePage.handleImport` → `unwrapStateFromZip` → `validateAppState` → `importAppState`, and `sync/server.ts` `pull` → `decryptState` → `validateAppState` → `importAppState`), so any manifest shape survives into IndexedDB.

**Design decision — inline vs `$ref`.** The task note suggests either inlining `packManifest.schema.json`'s constraints or `$ref`-ing it. We **inline** the constraints because the two schemas describe *related but distinct* trust surfaces:

- `packManifest.schema.json` describes the CDP wire format — YAML files fetched from an arbitrary URL. That contract is deliberately narrow: it must not accept user-only client state.
- `appState.schema.json` describes a persisted app-state snapshot including *user-modified* manifest fields.

`PackManifest` in `src/types/index.ts` carries two fields (`decay`, `defaultXPSize`) that are set client-side by `PackOptionsModal.tsx` via `updatePackManifest` (`src/store/index.ts:342-357`) and legitimately appear in real backups. These fields are (correctly) absent from `packManifest.schema.json` — extending that CDP schema to accept them would widen the CDP contract for the wrong reason. Inlining a closed manifest sub-schema inside `appState.schema.json` keeps the two contracts independent and prevents surprising cross-effects (a change to the CDP contract silently loosening AppState validation, or vice versa).

**Change (single-file, schema-only).** Edit `src/schemas/appState.schema.json` only. Replace the current
```json
"manifest": { "type": "object" }
```
inside `packs.items.properties` with an object schema that mirrors the fields declared by `PackManifest` in `src/types/index.ts`, using `additionalProperties: false` and per-property types:

- `title`: `{ "type": "string", "minLength": 1 }` (required — matches `packManifest.schema.json`)
- `author`, `license`, `description`, `revision`, `revisionHistory`, `cdpCreatedAt`: `{ "type": "string" }` (optional)
- `chores`: `{ "type": "array", "items": { "type": "string", "pattern": "^[a-zA-Z0-9_-]+(\\.[a-zA-Z0-9_-]+)*\\.yaml$" } }` (optional — mirrors CDP schema, guards against path-traversal in exported/round-tripped manifests)
- `createdAt`: `{ "type": "string" }` (optional)
- `streak`: `{ "type": "boolean" }` (optional)
- `xpTarget`: `{ "type": "number", "minimum": 0 }` (optional)
- `targetDate`: `{ "type": "string", "pattern": "^\\d{4}-\\d{2}-\\d{2}$" }` (optional)
- `allowShiftOnImport`: `{ "type": "boolean" }` (optional)
- `decay`: `{ "type": "boolean" }` (optional — user-only field, not in CDP schema)
- `defaultXPSize`: `{ "oneOf": [{ "type": "string", "enum": ["XXS", "XS", "S", "M", "L", "XL", "XXL", "XXXL"] }, { "type": "number" }] }` (optional — user-only field, not in CDP schema)

Add `"required": ["title"]` and `"additionalProperties": false` on the manifest object.

**Scope.** No changes to `validate.ts`, `import.ts`, `ProfilePage.tsx`, `sync/server.ts`, `packManifest.schema.json`, or any application code. The `validateAppState` call already gates both ingress paths; tightening the schema is sufficient to reject a crafted manifest before `importAppState` writes anything to IndexedDB or before the encrypted-sync `pull` accepts the decrypted state.

**Compatibility.** `exportAppState` (`src/sync/export.ts`) writes the actual `Pack.manifest` objects out. Every field written by CDP import (`src/cdp/cdp-import.ts:107-130`) and by `updatePackManifest` (`src/store/index.ts:342-357`, called from `PackOptionsModal.tsx`) is enumerated in the list above, so legitimate export→import round-trips continue to validate. The seeded personal pack manifest (`{ title: 'Personal' }`) also validates trivially.
