# CDP pack manifest can traverse directories via crafted chore filenames

**Status:** DONE
**Bug ID:** SEC-002
**Severity:** Medium

## Location
`src/cdp/cdp-import.ts`, lines 67–69 and 78–79

## Description
When importing a Chore Definition Pack (CDP), the server-supplied `__pack__.yaml` manifest contains a `chores` array of filenames. These filenames are assembled into fetch URLs without any sanitisation:

```ts
const choreUrl = `${baseUrl}/${filename}`;
const choreRes = await fetch(choreUrl);
```

A malicious pack author can include filenames like `../../other-dir/malicious.yaml` or `../secrets.yaml`. The browser's URL resolution normalises these, so:

```
baseUrl = https://raw.githubusercontent.com/evil/repo/main/packdir
filename = ../../outside/malicious.yaml
choreUrl = https://raw.githubusercontent.com/evil/repo/main/packdir/../../outside/malicious.yaml
         → https://raw.githubusercontent.com/evil/repo/main/outside/malicious.yaml
```

The `choreId` is derived directly from the filename with only `.yaml` stripped:
```ts
const choreId = filename.replace(/\.yaml$/, '');       // → '../../outside/malicious'
const choreKey = `${packId}/${choreId}`;               // → 'packdir/../../outside/malicious'
```

This leads to two exploitable paths:

**1. Serving chore data from outside the declared pack directory.** The user believes they are importing from `packdir/`, but the malicious manifest causes chore YAML files to be fetched from arbitrary paths within the same host. On a Git hosting service like GitHub, this means the pack author can reach any public file in any repository on raw.githubusercontent.com — including files uploaded by other users. For example, a chore filename of `../../../../../../other-user/other-repo/refs/heads/main/inject/malicious.yaml` resolves to a completely different repository. The schema validator `validateChoreDefinition` then runs on that third-party YAML, but if the schema is satisfied (a valid-looking chore definition) the data is imported and stored in the user's IndexedDB.

**2. Storing malformed keys in IndexedDB.** The `choreKey` (e.g., `packdir/../../outside/malicious`) is stored as the IndexedDB record key. Keys containing `..` segments violate the expected `{packId}/{choreId}` invariant relied on throughout the codebase. This can cause lookup failures, data corruption, or bypass of pack-scoped queries.

The JSON Schema for the pack manifest (`src/schemas/packManifest.schema.json`) only constrains chore items as `{ "type": "string" }` — no pattern validation on filename format. The fix should add a filename pattern that restricts entries to simple names (no path separators or `..` components).

## Validation
**Verdict: CONFIRMED — genuine, exploitable trust-boundary violation.**

Reachability: Any user who imports a CDP pack from a URL is exposed. No special access required — the attacker only needs to host a `__pack__.yaml` on any public Git repository.

Attacker control: The attacker fully controls the `chores` filenames in their pack manifest. The schema validation (`validatePackManifest`) only checks `items: { type: string }`, so any string including path-traversing ones is accepted.

Real-world impact: On GitHub's raw CDN (raw.githubusercontent.com), filenames like `../../../../other-user/other-repo/refs/heads/main/dir/chore.yaml` cause the browser to fetch YAML from a completely different user's repository. If that YAML satisfies the `validateChoreDefinition` schema, it is silently imported. The user cannot detect this — the UI shows the source URL they provided, not the actual fetch URLs for each chore. Separately, the `choreKey = packId + '/' + choreId` computed from the `..`-containing filename corrupts the IndexedDB key space used throughout the application.

The fix is straightforward: add a `pattern` constraint on the chore filename schema items.

## Fix Plan

**Two-layer fix:**

**Layer 1 — JSON Schema (primary defence):** Update `src/schemas/packManifest.schema.json` to restrict chore filename items to a safe pattern. A chore filename must be a simple name (no `/`, no `\`, no `..`) ending in `.yaml`:

```json
"chores": {
  "type": "array",
  "items": {
    "type": "string",
    "pattern": "^[a-zA-Z0-9_-]+(\\.[a-zA-Z0-9_-]+)*\\.yaml$"
  }
}
```

This pattern allows: `clean-up.yaml`, `morning-routine.yaml`, `chore_01.yaml`.
It rejects: `../evil.yaml`, `../../other.yaml`, `sub/dir.yaml`, `//evil.yaml`.

**Layer 2 — Runtime guard in cdp-import.ts (defence in depth):** After schema validation passes, add an explicit check in `fetchCDP` before assembling the URL:

```ts
const SAFE_FILENAME_RE = /^[a-zA-Z0-9_-]+(\.[a-zA-Z0-9_-]+)*\.yaml$/;
// inside the chores.map:
if (!SAFE_FILENAME_RE.test(filename)) {
  throw new Error(`Unsafe chore filename rejected: ${filename}`);
}
```

This ensures that even if the schema validator is bypassed (e.g., via a schema version mismatch or future refactor), filenames are still checked at the point of use.

**Why this is minimal:** Two targeted changes — one JSON schema update, one guard line. No new imports, no new dependencies.

### Test Plan

**File:** `src/cdp/cdp-import.test.ts`

**Test name:** `'parseChoreQuestions and fetchCDP reject filenames with path traversal'`

More specifically, add to the existing test file:

```ts
it('rejects chore filenames containing path traversal (..)', async () => {
  // Set up: mock fetch to serve a manifest with a traversal filename
  // The test should throw before any fetch of the chore file occurs
});
```

Since `fetchCDP` makes network calls, the cleanest test approach is to test the schema validation path: `validatePackManifest` should reject a manifest whose `chores` array contains `../evil.yaml`.

**Test file:** `src/schemas/validate.test.ts`

**Exact test:**
```ts
it('rejects pack manifest with path-traversal chore filename', () => {
  const result = validatePackManifest({
    title: 'Test Pack',
    chores: ['../evil.yaml'],
  });
  expect(result.valid).toBe(false);
});

it('accepts pack manifest with safe chore filename', () => {
  const result = validatePackManifest({
    title: 'Test Pack',
    chores: ['morning-routine.yaml', 'chore_01.yaml'],
  });
  expect(result.valid).toBe(true);
});
```

The traversal test must **fail** (currently `valid: true`) before the schema fix and **pass** (return `valid: false`) after.
