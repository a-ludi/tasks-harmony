# ReDoS via unguarded `regexPattern` in `validateAnswer`

**Status:** DONE
**Bug ID:** SEC-000005
**Severity:** Medium

## Location
`src/questions/validation.ts`, lines 40–43

Secondary surfaces:
- `src/schemas/choreDefinition.schema.json`, line 49 (`regexPattern` unconstrained)
- `src/schemas/appState.schema.json`, line 23 (`regexPattern` unconstrained)

## Description

### The vulnerability

`validateAnswer` in `src/questions/validation.ts` compiles `question.regexPattern` directly with `new RegExp(question.regexPattern)` (lines 40–41) and then executes it against user-supplied text, with no prior safety check:

```ts
if (question.type === 'TEXT' && question.regexPattern && typeof value === 'string') {
  const re = new RegExp(question.regexPattern);   // ← no isSafeRegex guard here
  if (!re.test(value)) { … }
}
```

The codebase already defines `isSafeRegex()` in the same file (lines 8–26) precisely to detect catastrophic-backtracking patterns. It is correctly called in two form-UI code paths that validate *locally-authored* regex patterns (`choreFormValidation.ts:29` and `QuestionFormFields.tsx:34`). However, `validateAnswer` — the function that actually *executes* the regex at completion time — never calls `isSafeRegex`.

### Attack vector

The gap is fully exploitable via a malicious CDP (Chore Definition Pack):

1. An attacker publishes a CDP whose `__pack__.yaml` lists a chore YAML file.
2. That YAML contains a `TEXT`-type question with a catastrophic regex in `regexPattern`, e.g.:
   ```yaml
   questions:
     - id: q1
       type: TEXT
       prompt: "Enter your answer"
       required: true
       regexPattern: "^(a+)+$"
   ```
3. The `choreDefinition.schema.json` validates `regexPattern` only as `{ "type": "string" }` — any string passes.
4. The file passes `validateChoreDefinition`, is stored in IndexedDB, and the pack imports successfully with no warning.
5. When the user opens the "Complete Chore" modal and types any text into the question field, `validateAnswer` compiles `^(a+)+$` via `new RegExp(...)` and calls `.test(value)`. A carefully constructed input such as `"aaaaaaaaaaaaaaaaaaaab"` causes exponential backtracking, hanging the browser's main thread.

### Why this is different from the existing form-UI guard

The `isSafeRegex` checks in the form UI only run when a user *creates or edits* a question through the local chore editor. They do not run during:

- CDP import (`fetchCDP` in `src/cdp/cdp-import.ts`)
- Sync import (`importAppState` in `src/sync/import.ts`) — an encrypted blob from a compromised or attacker-controlled sync endpoint could inject a bad `regexPattern`
- Backup restore (`src/backup/backup.ts`)

Any of these entry points can populate IndexedDB with a question containing a malicious `regexPattern`. Once stored, `validateAnswer` will execute it without a guard.

### Impact

- **Browser main-thread hang / tab freeze** triggered by the victim simply trying to complete a chore. No special skill required beyond hosting a malicious CDP.
- Repeated exposure each time the completion modal is opened (the pattern is stored permanently in IndexedDB).
- The attack is silent and produces no error — the browser just hangs.

## Validation

**CONFIRMED — genuine, exploitable ReDoS.**

All claims were verified against the actual source code:

1. **The vulnerable call exists exactly as described.** `validateAnswer` in `src/questions/validation.ts` lines 40–41 compiles `question.regexPattern` with `new RegExp(...)` and immediately calls `.test(value)` with no safety check.

2. **`isSafeRegex` is present but not called here.** It is defined in the same file (lines 8–26) and is correctly imported and used in `choreFormValidation.ts:29` and `QuestionFormFields.tsx:34`. Those guards protect only the local chore-editor UI. `validateAnswer` — the execution-time path — is unguarded.

3. **All three external import paths bypass the guard.** `fetchCDP` (cdp-import.ts) parses questions with `parseChoreQuestions`, which does a raw spread with no regex safety check. `importAppState` (sync/import.ts) writes questions straight to IndexedDB from the decrypted blob. Both paths populate IndexedDB without ever calling `isSafeRegex`.

4. **The schemas impose no constraint.** Both `choreDefinition.schema.json:49` and `appState.schema.json:23` declare `regexPattern` as `{ "type": "string" }` only — any string, including catastrophic patterns, passes validation.

5. **Attacker control is full.** A public CDP is a low-barrier delivery mechanism: the attacker merely hosts a YAML file. No authentication or existing relationship with the victim is required. The sync blob path requires a compromised or attacker-controlled sync endpoint, making it a secondary (higher-privilege) vector.

6. **Impact is confirmed.** Patterns such as `^(a+)+$` with an input like `"aaaaaaaaaaaaaaaaaaaab"` are classic ReDoS inputs that will hang the JavaScript main thread in all major browsers. The hang occurs every time the completion modal is opened for the affected chore, since the pattern is stored persistently in IndexedDB with no re-validation on load.

**Severity rationale — Medium (not High):** The attack produces a denial-of-service (tab freeze / unresponsive UI) rather than data exfiltration, remote code execution, or authentication bypass. The victim must actively install a malicious CDP (a user-initiated action) or be on a compromised sync endpoint. There is no path to persistent system-level compromise. A Medium rating is appropriate: the impact is user-visible and repeatable, the attack is low-skill, but confidentiality and integrity are not directly affected.

## Fix Plan

### Approach

In `src/questions/validation.ts`, guard the `new RegExp(question.regexPattern)` call inside `validateAnswer` by calling `isSafeRegex(question.regexPattern)` first. If `isSafeRegex` returns `{ valid: false }`, return its `error` message immediately instead of compiling and running the regex.

The change is a two-line insertion in the existing `if` block at lines 40–45. No new helpers, no schema changes, no other files touched.

Concretely, replace:

```ts
if (question.type === 'TEXT' && question.regexPattern && typeof value === 'string') {
  const re = new RegExp(question.regexPattern);
  if (!re.test(value)) {
    return `Value does not match the required pattern: ${question.regexPattern}`;
  }
}
```

with:

```ts
if (question.type === 'TEXT' && question.regexPattern && typeof value === 'string') {
  const safetyCheck = isSafeRegex(question.regexPattern);
  if (!safetyCheck.valid) {
    return safetyCheck.error ?? 'Invalid regex pattern';
  }
  const re = new RegExp(question.regexPattern);
  if (!re.test(value)) {
    return `Value does not match the required pattern: ${question.regexPattern}`;
  }
}
```

That is the complete fix. No other files need modification.
